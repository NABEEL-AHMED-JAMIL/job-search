PROBLEM YOU HAD
═══════════════════════════════════════════════════════════════════════════

Your sender side has proper callback handling:
```java
kafkaTemplate.send(topic, key, payload)
    .addCallback(
        result -> handleSendSuccess(result, payload, sourceJob, jobQueue),
        ex -> handleSendFailure(ex, payload, sourceJob, jobQueue)
    );
```

But your Python listeners were using auto-commit, which could cause:
❌ Duplicate message processing
❌ Messages acknowledged before processing
❌ No way to retry on failure

Each listener now follows the same pattern as your sender side.

═══════════════════════════════════════════════════════════════════════════
BEFORE vs AFTER
═══════════════════════════════════════════════════════════════════════════

BEFORE (Auto-commit - Problem):
────────────────────────────────────────────────────────────────────────────
enable_auto_commit=True

1. Message received
2. Offset committed (auto)
3. Processing starts
4. Processing fails
5. ❌ Problem: Message already committed, won't be retried

AFTER (Manual commit - Solution):
────────────────────────────────────────────────────────────────────────────
enable_auto_commit=False

1. Message received
2. Processing starts
3. Processing succeeds
4. consumer.commit()  ✓ Acknowledged
5. ✅ Message won't be retried (it succeeded)

OR

1. Message received
2. Processing starts
3. Processing fails
4. (no commit)  ✗ Not acknowledged
5. ✅ Message will be retried (it failed)

ARCHITECTURE COMPARISON
═══════════════════════════════════════════════════════════════════════════

YOUR SENDER SIDE (Java/Spring):
```
kafkaTemplate.send(topic, key, message)
       ↓
sendAsync()
       ↓
   Success?
    ↙    ↖
  YES    NO
   ↓      ↓
handleSendSuccess()  handleSendFailure()
      ↓                   ↓
   Log OK           Log Error + Retry
```

OUR RECEIVER SIDE (Python):
```
consumer.poll()
       ↓
process_*_message(value)
       ↓
   Success?
    ↙    ↖
  YES    NO
   ↓      ↓
consumer.commit()    (skip commit)
      ↓                   ↓
Message acknowledged  Message NOT acknowledged
      ↓                   ↓
Won't be reprocessed  Will be reprocessed
```

MESSAGE PROCESSING LOOP:
────────────────────────
for message in consumer:
    try:
        if message.value is not None:
            logger.info(f"Received: {message.value}")

            # Call process function that returns True/False
            success = process_test_message(message.value)

            # Acknowledge ONLY if successful
            if success:
                consumer.commit()  # ← Acknowledge
                logger.info(f"Message acknowledged - offset: {message.offset}")
            else:
                logger.warning(f"Message NOT acknowledged - offset: {message.offset}")

    except Exception as msg_err:
        logger.error(f"Error: {str(msg_err)}")
        # Don't commit - will retry
        continue

PROCESS FUNCTION:
─────────────────

        logger.info("Processed successfully")
        return True  # ← Success signal

    except Exception as e:
        logger.error(f"Failed: {str(e)}", exc_info=True)
        return False  # ← Failure signal

def process_scrapping_message(message):

        logger.info(f"Processing scrapping message: {message}")

        # Parse message
        if isinstance(message, dict):
            data_id = message.get('id')
            data_value = message.get('value')
        else:
            data_id = message
            data_value = None

        # Validate data
        if not data_id or not data_value:
            logger.error("Invalid message: missing id or value")
            return False  # ← Failure: invalid input

        # Business logic here (e.g., database insert)
        # insert_to_database(data_id, data_value)
        logger.info(f"Saved to database: id={data_id}, value={data_value}")

        return True  # ← Success: data saved

    except DatabaseError as e:
        logger.error(f"Database error: {str(e)}", exc_info=True)
        return False  # ← Failure: database error

    except Exception as e:
        logger.error(f"Unexpected error: {str(e)}", exc_info=True)
        return False  # ← Failure: unexpected error
